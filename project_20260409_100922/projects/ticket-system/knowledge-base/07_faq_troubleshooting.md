# 常见问题解答与故障排除

## 用户常见问题

### 账户与登录
#### Q1: 如何注册账号？
A: 访问系统首页，点击"注册"按钮，填写用户名、密码、邮箱等信息即可注册。用户名需4-20位字母数字组合，密码需8-20位且包含字母和数字。

#### Q2: 忘记密码怎么办？
A: 目前系统暂不支持密码找回功能，请联系管理员重置密码。未来版本将增加邮箱验证重置功能。

#### Q3: 为什么登录失败？
A: 可能的原因：
1. 用户名或密码错误
2. 账户已被禁用
3. 连续多次登录失败被暂时锁定
4. 网络连接问题

#### Q4: 可以多设备同时登录吗？
A: 可以，系统支持多设备同时登录，使用相同的JWT令牌。

### 车票查询与预订
#### Q5: 如何查询车票？
A: 有三种方式：
1. 在车票查询页面输入出发站、到达站、日期查询
2. 通过智能客服语音或文字查询："帮我查一下北京到上海的高铁"
3. 使用AI工具调用查询接口

#### Q6: 车票价格是如何计算的？
A: 票价基于车次类型、席别类型和运营成本计算：
- 高铁/动车：商务座 > 一等座 > 二等座
- 普通列车：软卧 > 硬卧 > 软座 > 硬座 > 无座
具体价格以查询时显示为准。

#### Q7: 为什么查询不到某些车次？
A: 可能的原因：
1. 车次已停运或调整
2. 查询日期不在售票期内（一般为30天内）
3. 出发站或到达站名称不准确
4. 系统缓存未更新，尝试清除缓存或稍后重试

#### Q8: 余票信息是实时的吗？
A: 余票信息有1分钟的缓存，基本保证实时性。在购票高峰期，可能会有短暂延迟。

### 订单与支付
#### Q9: 创建订单后多久需要支付？
A: 订单创建后需在30分钟内完成支付，超时订单将自动取消。

#### Q10: 支持哪些支付方式？
A: 当前版本为演示系统，使用模拟支付流程。实际生产环境可集成微信支付、支付宝、银联等支付渠道。

#### Q11: 支付成功后如何获取车票？
A: 支付成功后系统会自动生成电子车票，可在"我的订单"中查看票号和座位号。当前版本为模拟系统，实际乘车需使用12306官方渠道。

#### Q12: 可以修改订单信息吗？
A: 订单创建后，在支付前可以取消订单重新购买。支付成功后无法修改订单信息，如需变更需办理退票后重新购买。

### 退票与改签
#### Q13: 退票手续费如何计算？
A: 根据铁路部门规定：
- 发车前48小时以上：扣除票价5%
- 发车前24-48小时：扣除票价10%
- 发车前2-24小时：扣除票价20%
- 发车前2小时内：不可退票

#### Q14: 如何办理退票？
A: 在"我的订单"中找到需要退票的订单，点击"退票"按钮，选择退票原因即可。退款将在1-7个工作日内原路返回。

#### Q15: 可以改签车票吗？
A: 当前版本暂不支持在线改签，如需改签请先办理退票后重新购买。

### 乘客管理
#### Q16: 最多可以添加多少常用乘客？
A: 每个用户最多可添加20个常用乘客。

#### Q17: 乘客信息会安全存储吗？
A: 是的，乘客身份证号使用AES加密存储，手机号进行脱敏显示，确保用户隐私安全。

#### Q18: 可以为他人的购票吗？
A: 可以，只要将他人添加为常用乘客，即可为其购票。

### 智能客服
#### Q19: 智能客服能做什么？
A: 智能客服可以：
1. 回答购票相关咨询
2. 查询车次和余票
3. 帮助创建订单、查询订单、办理退票
4. 管理常用乘客
5. 解答系统使用问题

#### Q20: 智能客服的回答准确吗？
A: 智能客服基于RAG（检索增强生成）技术，结合系统知识库和业务工具，能够提供准确回答。如果遇到无法回答的问题，会建议您联系人工客服。

#### Q21: 如何与智能客服对话？
A: 在页面右下角点击客服图标，输入问题即可。支持自然语言，如："帮我查一下明天北京到上海的高铁"。

#### Q22: 客服对话记录会保存吗？
A: 会保存最近的对话记录，用于改善服务质量和用户个性化体验。您可以在设置中清除对话历史。

## 管理员运维问题

### 系统部署
#### Q23: 系统运行环境要求是什么？
A: 最低要求：
- Java 17+
- MySQL 8.0+
- Node.js 16+（前端）
- 4GB RAM
推荐配置：
- Java 17
- MySQL 8.0
- Redis 6.0+（可选，用于分布式缓存）
- 8GB RAM
- 多核CPU

#### Q24: 如何部署系统？
A: 部署步骤：
1. 导入数据库脚本（database/init.sql）
2. 配置后端application.yml（数据库连接、JWT密钥等）
3. 启动后端Spring Boot应用
4. 配置前端环境（修改API地址）
5. 启动前端开发服务器或构建生产版本
6. （可选）启动Ollama服务用于本地AI模型

#### Q25: 如何配置AI模型？
A: 在application.yml中配置：
```yaml
ai:
  model:
    provider: "ollama"  # 或 "openai", "http-api"
    ollama:
      base-url: "http://localhost:11434"
      model-name: "llama3.2:3b"
```

### 数据库管理
#### Q26: 数据库备份怎么做？
A: 建议定期备份MySQL数据库：
```bash
# 备份命令
mysqldump -u root -p ticket_system > backup_$(date +%Y%m%d).sql

# 恢复命令
mysql -u root -p ticket_system < backup_file.sql
```

#### Q27: 数据库性能优化建议？
A: 
1. 为常用查询字段创建索引
2. 定期清理过期数据（如已完成订单）
3. 使用数据库连接池
4. 监控慢查询日志

### 知识库管理
#### Q28: 如何更新知识库？
A: 两种方式：
1. 在knowledge-base目录下添加或修改Markdown文档，重启系统后自动同步
2. 通过管理接口动态添加知识：
```bash
curl -X POST /api/knowledge/add \
  -H "Authorization: Bearer {token}" \
  -d '{"title":"新知识","content":"内容","category":"FAQ"}'
```

#### Q29: 知识库文档格式有什么要求？
A: 建议使用Markdown格式，结构清晰。系统会自动：
1. 按段落分割文档
2. 生成文本向量
3. 存储到ChromaDB向量数据库

#### Q30: 如何查看知识库使用情况？
A: 调用监控接口：
```bash
curl /api/ai/health
```
返回信息包含知识库大小、检索统计等。

### 故障排除
#### Q31: 系统启动失败，报数据库连接错误
A: 检查步骤：
1. MySQL服务是否启动
2. application.yml中的数据库配置是否正确
3. 数据库用户是否有足够权限
4. 防火墙是否阻止了数据库端口（3306）

#### Q32: 前端访问后端API出现CORS错误
A: 解决方案：
1. 确认后端CORS配置正确
2. 检查前端请求地址是否正确
3. 开发环境下确保Vite代理配置正确

#### Q33: AI服务不可用，聊天无响应
A: 排查步骤：
1. 检查AI模型配置是否正确
2. 如果使用Ollama，确认服务是否启动（http://localhost:11434）
3. 查看应用日志，是否有AI相关错误
4. 尝试切换AI模型提供商（如从Ollama切换到HTTP-API）

#### Q34: 车票库存数据不一致
A: 处理方案：
1. 检查库存扣减的事务逻辑
2. 验证并发控制机制（行锁、乐观锁）
3. 核对订单表和库存表的关联数据
4. 如有必要，执行库存数据校准脚本

#### Q35: 用户反馈订单支付后状态未更新
A: 排查方向：
1. 检查支付回调处理逻辑
2. 查看订单状态机转换是否正确
3. 确认缓存清除是否及时
4. 检查定时任务是否正常执行

## 开发者调试指南

### 本地开发环境
#### Q36: 如何搭建本地开发环境？
A: 
1. 克隆代码库
2. 导入IDE（推荐IntelliJ IDEA或VS Code）
3. 安装依赖：后端使用Maven，前端使用npm
4. 配置本地数据库
5. 启动后端应用（运行TicketSystemApplication）
6. 启动前端开发服务器（npm run dev）

#### Q37: 如何进行单元测试？
A: 后端测试：
```bash
# 运行所有测试
mvn test

# 运行特定测试类
mvn test -Dtest=OrderServiceTest
```

前端测试：
```bash
# 运行单元测试
npm run test:unit

# 运行端到端测试
npm run test:e2e
```

#### Q38: 如何调试AI服务？
A: 调试方法：
1. 启用DEBUG级别日志：`logging.level.com.ticket.service.ai=DEBUG`
2. 查看AI请求和响应日志
3. 使用测试工具验证RAG检索效果
4. 监控向量数据库操作

### API调试
#### Q39: 如何测试API接口？
A: 推荐使用工具：
1. Postman - 功能全面的API测试工具
2. curl - 命令行工具，适合简单测试
3. Swagger UI - 访问 http://localhost:8080/swagger-ui.html

#### Q40: API返回统一错误格式是什么？
A: 所有错误返回统一格式：
```json
{
  "success": false,
  "code": "ERROR_CODE",
  "message": "错误描述",
  "data": null,
  "timestamp": "2026-04-20T14:30:25.123Z"

```

### 性能调优
#### Q41: 如何监控系统性能？
A: 监控方案：
1. Spring Boot Actuator：提供健康检查、指标收集
2. 应用日志：记录关键操作耗时
3. 数据库慢查询日志
4. JVM监控：内存使用、GC情况

#### Q42: 系统响应慢如何优化？
A: 优化方向：
1. 数据库查询优化：添加索引、减少JOIN
2. 缓存策略优化：增加缓存命中率
3. AI服务优化：模型量化、缓存推理结果
4. 前端优化：代码分割、懒加载

### 版本升级
#### Q43: 如何升级到新版本？
A: 升级步骤：
1. 备份当前数据库和配置文件
2. 停止旧版本服务
3. 部署新版本代码
4. 执行数据库迁移脚本（如果有）
5. 启动新版本服务
6. 验证功能正常

#### Q44: 升级后数据迁移需要注意什么？
A: 注意事项：
1. 确保数据迁移脚本的幂等性
2. 在大数据量时分批处理
3. 迁移前做好完整备份
4. 提供回滚方案

## 铁路常识

### 购票规则
#### Q45: 儿童票购买标准是什么？
A: 根据铁路规定：
- 身高1.2米以下：免票（不占座）
- 身高1.2-1.5米：儿童票（半价，有座）
- 身高1.5米以上：全价票
- 每名成人可免费携带一名1.2米以下儿童

#### Q46: 学生票购买条件是什么？
A: 购买学生票需满足：
1. 在国家教育主管部门批准有学历教育资格的学校就读
2. 家庭居住地和学校不在同一城市
3. 凭附有加盖院校公章的减价优待凭证
4. 每年乘车次数限于四次单程

#### Q47: 军人票如何购买？
A: 现役军人和残疾军人凭有效证件购买优待票，具体政策以铁路部门最新规定为准。

### 乘车须知
#### Q48: 需要提前多久到达车站？
A: 建议：
- 高铁/动车：提前30-60分钟
- 普通列车：提前60-90分钟
- 节假日高峰期：再提前30分钟

#### Q49: 可以带多少行李？
A: 免费携带品重量和体积：
- 儿童（含免费儿童）10kg，外交人员35kg
- 每件物品外部尺寸长、宽、高之和不超过160cm
- 杆状物品不超过200cm
- 动车组列车不超过130cm

#### Q50: 哪些物品禁止携带？
A: 禁止携带物品包括但不限于：
1. 枪支、弹药、警械、管制刀具
2. 爆炸物品、易燃易爆物品
3. 毒害品、腐蚀性物品
4. 放射性物品、传染病病原体
5. 国家法律、法规规定的其他禁止携带的物品
