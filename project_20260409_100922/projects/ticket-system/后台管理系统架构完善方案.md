## 2. 缺失模块识别

### 2.1 权限控制机制
**问题**: 当前仅有认证拦截器(AuthenticationInterceptor)，缺乏权限校验逻辑
**影响**: 任何登录用户均可访问所有管理接口，存在安全风险

**解决方案**:
1. 创建权限拦截器 `PermissionInterceptor`
2. 基于RBAC权限表中的API权限进行URL匹配
3. 支持白名单（如公开API）
4. 缓存用户权限提升性能

### 2.2 数据可视化模块
**问题**: 仪表盘数据为模拟数据，缺乏真实统计接口
**影响**: 管理员无法实时了解系统运行状态

**解决方案**:
1. 创建统计服务 `StatsService`
2. 提供以下统计接口：
   - 用户总数、今日新增
   - 订单总数、今日订单、销售额统计
   - 车次总数、运行中车次
   - 知识库条目数
   - 系统访问量趋势
3. 前端图表优化：使用ECharts或Element Plus Charts

### 2.3 操作日志模块
**问题**: 缺乏管理员操作审计功能
**影响**: 无法追踪系统变更，不符合安全合规要求

**解决方案**:
1. 创建操作日志实体 `OperationLog`
2. 设计操作日志表 `operation_log`
3. 创建AOP切面记录关键操作
4. 提供日志查询接口

### 2.4 系统监控模块
**问题**: 缺乏系统健康状态监控
**影响**: 无法及时发现系统异常

**解决方案**:
1. 集成Spring Boot Actuator
2. 自定义健康检查（数据库连接、Redis连接、AI服务状态）
3. 提供监控仪表板

## 4. 架构改进方案

### 4.1 权限控制架构
```
请求流程:
用户请求 → AuthenticationInterceptor (认证) → PermissionInterceptor (权限校验) → Controller
```

**核心组件**:
1. `PermissionInterceptor`: 权限校验拦截器
2. `PermissionService`: 权限查询服务（支持缓存）
3. `@RequiresPermission`: 权限注解（备用方案）

**缓存策略**:
- 用户权限缓存：10分钟
- 权限URL映射缓存：30分钟

### 4.2 操作日志架构
```
记录时机:
1. 用户登录/登出
2. 数据增删改操作
3. 权限变更操作
4. 系统配置变更
```

**表结构设计**:
```sql
CREATE TABLE `operation_log` (
    `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
    `user_id` BIGINT COMMENT '操作用户ID',
    `username` VARCHAR(50) COMMENT '用户名',
    `operation` VARCHAR(100) NOT NULL COMMENT '操作类型',
    `module` VARCHAR(50) COMMENT '操作模块',
    `description` VARCHAR(500) COMMENT '操作描述',
    `request_method` VARCHAR(10) COMMENT '请求方法',
    `request_url` VARCHAR(500) COMMENT '请求URL',
    `request_params` TEXT COMMENT '请求参数',
    `ip_address` VARCHAR(50) COMMENT 'IP地址',
    `user_agent` VARCHAR(500) COMMENT '用户代理',
    `status` TINYINT DEFAULT 1 COMMENT '操作状态 1-成功 0-失败',
    `error_message` TEXT COMMENT '错误信息',
    `execution_time` INT COMMENT '执行耗时(ms)',
    `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP
) COMMENT='操作日志表';
```

### 4.3 数据统计架构
**统计维度**:
1. 实时统计：用户数、订单数、销售额
2. 趋势统计：日/周/月增长趋势
3. 业务统计：车次上座率、退票率、客服满意度

**接口设计**:
```java
@RestController
@RequestMapping("/api/admin/stats")
public class AdminStatsController {
    // 1. 核心数据概览
    @GetMapping("/overview")
    public Result<StatsOverview> getOverview();
    
    // 2. 趋势数据
    @GetMapping("/trend/{type}") // type: daily, weekly, monthly
    public Result<List<TrendData>> getTrend(@PathVariable String type);
    
    // 3. 业务报表
    @GetMapping("/report/{reportType}")
    public Result<ReportData> getReport(@PathVariable String reportType);
}
```

### 4.4 系统监控架构
**监控项**:
1. 服务健康：数据库、Redis、AI服务
2. 性能指标：接口响应时间、QPS
